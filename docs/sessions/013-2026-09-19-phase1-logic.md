## Bugs found & fixed this session (each with regression coverage)

1. **Wipe loop used `table.user_id` for `User`** (whose column is `id`) —
   mypy caught it before first run; `users` is now deleted separately.
2. **FK-violation on first seed run** — root-caused empirically: SQLAlchemy
   2.0.36's unit of work orders flushes by `relationship()` dependencies
   ONLY; plain table-level FKs do NOT order inserts (proven with isolation
   tests). Fix: seed inserts flush in explicit dependency tiers (user → plan
   → tasks+decks → cards+rest), still one atomic commit. **Phase 2 note:
   mutation code must flush in FK order too, or add relationships.**
3. **Wrong test assertion** (my timezone-horizon test assumed a past horizon;
   next-midnight is always future) — fixed to `now < shanghai < london`, Δ=7h.
4. **Flaky-test scare = cross-agent DB contention, not a code bug** — while
   Agent S ran its own pytest concurrently, its session fixture dropped/
   recreated the shared `harbour_test` mid-run, causing transient
   `UndefinedTableError: relation "event_outbox" does not exist` in my
   SSE/upsert tests. Proven: identical tests pass in isolation and in the
   final uncontended full run (31 passed in 9.10s; a contended run took
   63s+ with 2 failures). **MONITOR ACTION ITEM: `harbour_test` is a shared
   mutable resource — only one agent may run the BE suite at a time, or each
   agent needs its own test-DB name.** Not patched around (§1.8); reported.
